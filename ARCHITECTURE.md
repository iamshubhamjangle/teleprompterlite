# Teleprompter Lite architecture

## Runtime and layout

Next.js App Router serves the public landing page at /, the workspace at /editor, and the same-origin output reader at /presenter. Interactive state lives in client components. Tailwind and shadcn components provide controls; all custom styles live in src/app/globals.css, and authored workspace strings live in src/content/strings.en.ts. Public copy lives in src/content/seo.en.ts. next-themes controls light/dark surfaces, with a shared green primary and theme-specific accessible focus colors.

Workspace owns the Markdown draft, bookmarks, settings, playback, current reading anchor, countdown, and popup session. The left sidebar separates fixed header/tabs from scrolling Script and Bookmarks content; Script begins with the primary edit action, then import/export icon buttons followed by word/cue counts. The right sidebar has Settings and Layout tabs; Settings sections use increased vertical rhythm between controls; Layout provides presets, configuration transfer, and local clearing. When collapsed, its rail exposes only those two destinations, apart from the panel expand control. Reader width and height are adjusted directly in the pane. The center contains the reader and bottom transport, without a preview header/footer. Beside Next cue, the transport maps its compact speed dropdown values (1×, 2×, 3×, 4×, 5×, 8×, and 10×) to a 20 px/s base; popup and fullscreen actions remain adjacent at the end of the transport.

## Shared reading surface

Direct corrections activate only when a pointer lands inside a rendered text fragment's individual visible boxes, or the fragment receives keyboard focus. Preview text is otherwise noneditable. A capture-phase pointer listener rejects the blank space around or between wrapped text boxes, commits and blurs any current correction, clears its caret selection, and focuses the reader without scrolling. Clicking controls or outside the reader also ends a correction while preserving those controls' normal pointer behavior. Space after an outside click therefore controls playback instead of adding script whitespace. This applies to preview, native fullscreen, and fallback reading view.

Paused workspace previews support direct text corrections without opening ScriptEditor, including native fullscreen and fallback reading view. Each rendered text fragment is a plaintext contenteditable region while playback and countdown are stopped. The Markdown transform records source-column ranges so edits replace only visible text and retain surrounding formatting, line IDs, bookmarks, and reading anchors. Stable Markdown renderers and browser-owned text nodes preserve focus, selection, and native undo across input updates; anchor restoration waits while a correction has focus. Plain-text paste flattens newlines for minor corrections; Enter finishes the correction without inserting a new paragraph. IME composition commits on completion. Updates use Workspace's existing draft autosave and popup snapshots. The separate Edit action and full Markdown editor retain their existing behavior; standalone popup output remains read-only.

The reading guide supports the full 0–100% reading-area range through pointer dragging and arrow keys. Preferences, configuration imports, and popup geometry messages accept the same range. The line stays visible at the bottom edge; its separate handle is clamped inside the pane at both edges, and width handles stay reachable across the full range. Script padding and anchor restoration continue to use the guide's logical percentage.

Native fullscreen and the workspace fallback reading view include a plain-text bottom readout inside Reader's fullscreen element. It shows the current font size in pixels and the scroll-speed multiplier using the transport's 20 px/s base, updating directly from shared settings. The readout occupies its own row below the reading stage and any mobile fullscreen controls, remains unmirrored, and accounts for the device bottom safe area.

The shared sourceAnchors Markdown transform renders single source newlines as explicit line breaks in prose, including formatted text and list continuations. Blank lines still separate paragraph cues; existing Markdown hard breaks are preserved without duplication, and code blocks retain literal newlines. Source-line anchors and bookmark targets remain tied to the original script lines. Workspace preview, native fullscreen, fallback reading view, and popup output all use this transform. Reader regression tests cover these paths without launching a UI preview.

Reader renders Markdown as paragraph cues, with stable source-line anchors for bookmarks and reflow restoration. Bookmark actions sit at the far left of each source line in a reserved gutter, with always-visible primary-color outline icons for inactive lines, filled icons for saved bookmarks, and pressed-state highlighting. List items, including nested and formatted content, retain source anchors for navigation but omit inline bookmark actions so bullet and number markers remain clear; the separate bookmark strip remains available for navigation. Width handles adjust symmetric margins while preserving imported asymmetry. A narrow window initially widens an overly narrow saved column; directly operating a width handle starts from those displayed margins and overrides the fallback so each adjustment takes effect immediately. Height handles adjust 20–100% reading height, leaving 0–80% phone clearance. The Bookmarks and Phone clearance preferences apply identically in the workspace preview, native fullscreen, fallback reading view, and popup output. In the workspace, the reservation label and divider hint sit inside a compact phone outline with speaker and home indicators. The phone retains a fixed 112px minimum width and 176px height; reduced clearance clips its lower portion behind the footer instead of shrinking it. The reading guide and its pointer/keyboard handle render whenever enabled in preview, native fullscreen, fallback reading view, and popup output. Its line uses the primary accent. The up/down adjustment control is always visible whenever the guide is rendered, at the reader's far-left edge with left: 0 and margin-left: 0; it does not require hover or focus. Its sidebar position field is intentionally omitted.

The same handles work in workspace, native fullscreen, fallback reading view, and popup output. Width and height output handles reveal on hover/focus and stay visible on touch; the reading-guide adjuster stays visible for every input type. The height handle stays within the pane at 100% height and is hidden when Phone clearance is disabled. Resizing pauses and resumes the prior playback state. Geometry changes preserve the current logical reading anchor.

Playback uses elapsed animation-frame time and a fractional scroll accumulator to avoid low-speed rounding loss. Wheel input uses native script scrolling during both playback and pause across the workspace, native fullscreen, fallback reading view, and popup output. Reader does not intercept wheel events or change speed; playback resumes from the manually scrolled position. Ctrl/Meta wheel preserves browser zoom.

## Data and persistence

src/lib/model.ts contains schemas, defaults, paragraph grouping, line reconciliation, geometry bounds, and playback calculations. First-use and reset defaults on desktop and mobile use 24px font size, 1.4 line height, and 20 px/s scroll speed. Preview Options enable Bookmarks bar, Focus mode, Reading guide, and the 3-second countdown; mirror, phone mode (output clearance), and screen awake are disabled. Previously saved preferences remain intact.
Focus mode renders non-current cues at a fixed 50% opacity. Its compatibility setting is normalized on preference restoration and configuration import; it is not exposed as a user control. The right sidebar groups Focus mode, Reading guide, countdown, screen-awake, and output settings under Preview Options.

Versioned localStorage envelopes save settings and the current draft, title metadata, bookmarks, and anchor. The title remains internal metadata; no script-title control appears in the sidebar. Hydration restores data after mount, and reload always starts paused. Imports are validated before applying; export provides portable Markdown or configuration JSON.

## Popup synchronization

src/lib/protocol.ts validates messages over BroadcastChannel, with same-origin postMessage fallback. Workspace is the authoritative controller; Presenter owns the animation loop while connected. Snapshots include settings, bookmarks, script, theme, playback, the active countdown, and anchor, so the popup renders the same pre-play countdown as the workspace. Commands synchronize playback and cue navigation; progress carries the output anchor back to the controller and restores the main reader to the same logical line/fraction. Main-reader manual scrolling and cue jumps send anchors to the popup. Silent follower restores update cue highlighting without echoing progress; programmatic scroll events are suppressed to prevent feedback loops. Only the popup runs playback while connected. An open popup is not disconnected solely for delayed heartbeats when browser timers are throttled.

Presenter sends validated geometry patches for margins, height, reading-guide position, and output-clearance activation, plus the existing speed message. Geometry is applied optimistically in output, then reflected in controller snapshots and local persistence. The geometry message rejects unknown properties and out-of-range values. Disconnected output keeps its own local state and pauses safely when its controller closes.

## Selection editing and empty-state recovery

ScriptEditor owns transient selection state around its controlled Markdown textarea. An always-visible toolbar provides labeled formatting actions for bold, italic, strikethrough, inline code, heading, quote, and lists. Native textarea select and document selectionchange events keep toolbar visibility synchronized for touch handles and menu-based selection. Pointer actions preserve focus and selection across mouse, touch, and pen; formatting actions and keyboard shortcuts read the current textarea range to avoid stale React selection state. With no selected text, toolbar actions and shortcuts format the entire source line containing the caret; an explicit selection retains its existing behavior. Keyboard shortcuts support bold, italic, strikethrough, and code. The pure formatter preserves unselected content, applies block actions to whole selected lines, and formats separate paragraphs independently so reader cues retain valid Markdown. Pending selection restoration runs after the controlled text update. Editing continues through Workspace's existing reconciliation and persistence.

Reader accepts an optional onEditScript callback. An empty workspace reader explains how to start and opens the focused ScriptEditor directly, while clearing fallback output and pausing playback. Output-only readers point users back to Edit script in the workspace.

The workspace empty reader presents larger New script and Try a Sample actions beneath its guidance. New script opens the existing blank editor flow; Try a Sample restores the built-in sample script. The sample action uses an animated four-color gradient with a soft matching glow, disabled for reduced-motion users. The workspace-only instructional hint is omitted; output-only readers retain their workspace guidance. Desktop transport exposes labeled popup and fullscreen buttons, while mobile retains their compact icon treatment. Mobile stepwise speed controls use larger icon buttons with accessible tooltips.

## Global keyboard controls

Workspace and Presenter listen in the capture phase so focused buttons do not block global shortcuts or trigger duplicate Space activation. When Space controls playback, both keydown and its matching keyup are canceled and stopped before reaching the focused control. A ref retains the consumed press across playback/countdown renders, and window blur clears it. This prevents Base UI preview switches from toggling on release while keeping focus on the selected option. Text editing, sliders, comboboxes, listboxes, menus, dialogs, and controls used with shortcuts disabled retain native keyboard handling.

Up/Down navigates paragraph cues. Left/Right decreases/increases font size by 2px, clamped to the existing 18–96px range. Workspace updates persisted settings; Presenter sends validated fontSize settings patches to the controller and updates its snapshot. The popup protocol settings allowlist includes fontSize with the same schema bounds. Shortcut help, tips, sample text, and public guides use this mapping; focused reader resize handles retain their own arrow-key behavior.

### Reader editing actions

The shared Reader displays an always-visible top-right Edit button when Workspace supplies onEditScript. The action pauses playback, captures the reading anchor, exits native fullscreen or fallback reading view, and opens the desktop center editor or mobile Script editor. If native fullscreen exit fails, the existing recovery notice is shown and the current reader remains mounted. Reader groups Edit and fullscreen exit controls in its own fullscreen element; fallback exit uses Workspace's shared exitReading callback. Popup output remains an output surface without a script editor.

ScriptEditor receives shared Workspace callbacks for download, upload, Use Sample, New, and Save in both desktop and mobile edit screens. Download exports the current Markdown; upload reuses the validated file picker and existing replacement dialog. Use Sample restores the built-in script and clears old bookmarks/reading position while keeping editing open. New reuses the blank-draft/reset workflow. Save immediately writes the current draft, title, bookmarks, and reading anchor to the existing localStorage key before closing editing; storage failure leaves editing open with export guidance. Existing automatic saving remains active. The action row wraps on narrow screens and icon actions have accessible labels and tooltips.

## Mobile workspace navigation

At viewport widths up to 900px, the sidebars become full-screen tab destinations above a persistent five-item bottom navigation: Home, Script, Settings, Bookmark, and Layout. Sidebar rails, collapse controls, and internal sidebar tabs are hidden. Existing Script/bookmark and Settings/layout content is reused; the reader stays mounted beneath the destinations to preserve its position and is inert while another tab is open. Opening a control tab pauses playback. Cue/bookmark jumps return to Home. Escape returns to Home and exits editing. Script editing takes place inside the mobile Script destination; desktop editing continues in the center pane.

Home keeps the reader dominant and presents reset, previous, play/pause, next, speed, and fullscreen in one horizontal transport row. Mobile shows rotating tips at the end of Settings and hides the popup action and layout presets; configuration import/export and local-data clearing remain available in Layout. Mobile uses the same first-use and reset defaults as desktop. Valid saved preferences and imported configurations take precedence over defaults; resizing the viewport does not reset preferences.

### Starting a new script

The Script tab includes New script, which pauses playback and cancels countdown, clears lines, bookmarks and bookmark rename state, title, pending script import, reading anchor, cue/progress, and end-of-script state, then opens the blank ScriptEditor. A script revision remounts the reader and editor so old scroll/selection state cannot carry into the new draft. The blank draft is written immediately to the existing localStorage draft key, with normal debounced saving handling subsequent edits. Typography, playback preferences, layout configuration, and theme are retained. The action uses the same workflow on desktop and mobile, with the editor in the center pane on desktop and inside the Script destination on mobile.

### Sidebar cue following

Workspace keeps the active cue fully visible by adjusting only the left panel-scroll container when the cue leaves its viewport. Visible cues retain the existing scroll position; oversized cues align to the top. Cue changes, script updates, and returning to the Script destination refresh visibility. Automatic scrolling does not focus cue buttons or scroll the reader/page. On mobile, following runs only in the non-editing Script destination, and sidebar focus does not trigger desktop reveal behavior; bottom navigation remains the authority for tab selection.

## Public-release security maintenance

Next.js and its ESLint configuration use patched 16.4.4 releases; the lockfile refreshes compatible runtime and development dependencies. The shadcn development dependency remains required because globals.css imports shadcn/tailwind.css, in addition to its component-generation tooling. CI has read-only repository permissions, audits production dependencies, and verifies generated SEO artifacts. Dependabot checks npm and GitHub Actions weekly. Remaining development-only upstream advisories and validation evidence are recorded in PUBLIC-RELEASE-AUDIT.md; SECURITY.md documents private reporting and browser-local storage boundaries.

Root layout mounts the client SiteAnalytics wrapper. Its shared beforeSend filter drops presenter routes and malformed URLs, and strips search parameters and fragments from other event URLs. This prevents popup session identifiers and arbitrary URL data from entering application analytics; it does not control hosting/CDN logs. No script content or draft metadata is sent as custom telemetry. Regression tests exercise presenter exclusion and URL sanitization.

Next configuration removes the framework-identification header and adds MIME-sniffing protection, no-referrer policy, same-origin framing restrictions, and a limited CSP restricting base URLs and object embedding. The policy leaves Next inline scripts/styles, editor contenteditable behavior, same-origin popups, fullscreen, and wake lock available. It is not a nonce-based script execution policy. No app server or UI preview is started for local verification.

Real environment files, local audit evidence/history bundles, and Impeccable session caches are ignored. The public example contains only documented non-secret configuration. Recovery bundles and raw audit outputs remain in ignored .audit-local and must not be attached to public issues or releases.
